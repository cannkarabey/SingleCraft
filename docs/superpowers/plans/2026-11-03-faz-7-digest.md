# Faz 7 — Digest and alerts

**Spec:** `IMPLEMENTATION_PLAN.md` §4 profiles (digest_enabled, digest_hour, timezone, locale), niches.alert_threshold, §7 `send-digest` / `check-alerts`, §9 Faz 7; PDF §3.2 (Daily digest, Alert).
**Done (spec):** a test user receives the digest at the hour they set; the same story never triggers a second alert.

## Global Constraints

- Email via Resend in production (`RESEND_API_KEY`, `EMAIL_FROM`); locally, without a key, mail goes to the Supabase Mailpit (so it can be seen and tested). Production without a key fails loudly.
- Every email carries one-click unsubscribe (RFC 8058 `List-Unsubscribe` + `List-Unsubscribe-Post`) with an HMAC-signed token; no login needed.
- Idempotent sending: an `email_log` row per digest (user, local day) and per alert (user, story) with unique constraints, written before sending.
- Alerts: `final_score ≥ niche.alert_threshold`, at most 3 per user per local day.
- Digest content: top 5 Radar stories of the user's first niche (Discover top 5 if no niche), "Brief oluştur" deep links, and a "Yayınladın mı?" link for yesterday's unpublished brief.
- Templates in the Signal Terminal style, TR/EN by `profiles.locale`.
- Final whole-branch review skipped at the user's request.
